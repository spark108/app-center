# Spark108 App Center

Центр корпоративных приложений для Windows. WPF-клиент показывает персональный каталог, локальную библиотеку и обновления. ASP.NET Core обслуживает HTTP API и панель управления из одного контейнера. MariaDB хранит пользователей, права доступа, сеансы, каталог и метаданные релизов.

## Сервер в production

Разворачивайте Compose на Linux-хосте с Docker и Compose. Оба контейнера используют `network_mode: host`. По умолчанию MariaDB занимает `127.0.0.1:3307`, а веб-сервис — `127.0.0.1:8080`. Порты можно изменить в `.env`. HTTPS завершает обратный прокси на том же хосте.

1. Клонируйте `https://github.com/spark108/app-center.git` на сервер, например в `/opt/spark108/app-center`.
2. В настройках приложения в Alathea Auth зарегистрируйте точный Redirect URI `https://app.godish.ru/api/auth/callback`. На сервере создайте `.env` из [.env.example](.env.example) и заполните `ALATHEA_CLIENT_SECRET`, `MARIADB_PASSWORD` и `MARIADB_ROOT_PASSWORD`. Для паролей используйте разные случайные значения.
3. В клоне выполните `docker compose up -d --build`, затем `APP_CENTER_VERSION=1.0.0 bash scripts/rebuild-client.sh`. Для проверки состояния используйте `docker compose ps` и `docker compose logs app`.
4. Настройте DNS и HTTPS для `app.godish.ru`. Передавайте все пути на `127.0.0.1:8080`, сохраняя исходный путь. Установите допустимый размер запроса прокси минимум в 513 МиБ.
5. Откройте [панель управления](https://app.godish.ru/acp) и выполните первый вход. Первая успешно зарегистрированная учётная запись становится администратором. При развёртывании можно задать `ALATHEA_BOOTSTRAP_SUBJECT` с идентификатором `sub` владельца, чтобы закрепить за ним первый вход.

Шаблон `.env` включает Bake и цветной индикатор сборки в терминале. Для существующей установки перенесите в `.env` значения `COMPOSE_BAKE`, `COMPOSE_PROGRESS` и `COMPOSE_ANSI` из шаблона.

Пример конфигурации Caddy на хосте.

```caddyfile
app.godish.ru {
    reverse_proxy 127.0.0.1:8080
}
```

| Путь | Назначение |
| --- | --- |
| `/` | HTML-заглушка с HTTP 404 |
| `/acp` | Панель администратора |
| `/api` | HTTP API с Bearer-аутентификацией |
| `/api/auth/callback` | Серверный callback от Alathea Auth |
| `/healthz` | Проверка доступности веб-процесса |

Том `mariadb` содержит БД. Том `app_data` содержит ZIP-пакеты и ключи защиты браузерного сеанса. Для восстановления сервера резервируйте оба тома.

## Обновление с GitHub

При изменении API, панели или схемы выполните на сервере.

```bash
cd /opt/spark108/app-center && git pull --ff-only && docker compose up -d --build app
```

При изменении клиента или обновлятора передайте новый номер версии в `APP_CENTER_VERSION`. Скрипт собирает Windows x64 на сервере и сразу публикует пакет в системной карточке App Center. BuildKit хранит промежуточные файлы сборки во временном томе в памяти. Установленные клиенты получают обновление через HTTP API.

```bash
cd /opt/spark108/app-center && git pull --ff-only && APP_CENTER_VERSION=1.0.1 bash scripts/rebuild-client.sh
```

Чтобы узнать последнюю опубликованную версию, выполните следующую команду. Она выводит номер версии из каталога.

```bash
cd /opt/spark108/app-center && docker compose exec -T app dotnet Spark108.Server.dll --show-client-version true
```

Повторная сборка с тем же номером сохраняет зарегистрированный пакет и его состояние публикации.

## Первая установка клиента

Войдите в панель, скачайте скрипт по кнопке «Установщик Windows» и ZIP из системной карточки Spark108 App Center. Перенесите оба файла на Windows x64 и запустите в PowerShell.

```powershell
.\Install-AppCenter.ps1 -Package .\spark108-app-center-1.0.0.zip
```

Установку можно открыть из меню «Пуск». В карточке App Center нет кнопки запуска. При наличии новой версии клиент проверяет скачанный ZIP, перезапускается через отдельный обновлятор и восстанавливает предыдущие файлы, если новая версия не запустилась.

## Локальная сборка для разработки

На Windows x64 с .NET 10 SDK выполните из корня проекта.

```powershell
.\scripts\Build-Release.ps1 -Version 1.0.0
.\scripts\Install-AppCenter.ps1 -Package .\artifacts\Spark108-AppCenter-1.0.0-win-x64.zip
```

ZIP и файл SHA-256 появятся в `artifacts`. Сборка включает .NET и работает без отдельной установки среды выполнения. Установка создаёт ярлык в меню «Пуск» и размещает клиент в `%LOCALAPPDATA%\Spark108\AppCenter\client`. Для локальной отладки установщик принимает `-Origin http://127.0.0.1:8080`. Для отдельного профиля разработки можно задать `SPARK108_APP_CENTER_HOME` перед установкой и запуском.

Локальный ZIP можно вручную загрузить в тестовую панель App Center с тем же номером версии.

## Программы, версии и доступ

- Создайте **Программу** для переносимого Windows-приложения. Загрузите ZIP и укажите путь к EXE внутри него, например `bin/Tool.exe`. Клиент может открыть, обновить или удалить установленную программу.
- Создайте **Служебный компонент** для библиотеки, среды выполнения или набора файлов, который нужен другому пакету. В карточке зависимого пакета отметьте нужные компоненты. Клиент скачает и установит их до основного приложения. Компонент нельзя удалить, пока он нужен установленному пакету. Циклические зависимости запрещены.
- Используйте номер вида `1.2.3`. По умолчанию загруженная версия остаётся черновиком. Публикацию можно включить, снять и изменить описание выпуска. Последней считается наибольшая опубликованная версия. В клиенте для обычных пакетов можно выбрать более ранний опубликованный выпуск.
- Пользователи появляются в панели после первого входа через Alathea. Администратор может назначить им права, отключить вход или определить, кто видит конкретное приложение. Для установки пользователь должен иметь доступ и к основному пакету, и ко всем его компонентам.

Поддерживаются переносимые ZIP-пакеты до 512 МиБ. Программы и компоненты размещаются в отдельных папках по идентификатору в `%LOCALAPPDATA%\Spark108\AppCenter\apps`. При запуске приложение получает путь к этому корню в переменной `SPARK108_PACKAGES_DIR`. Храните изменяемые пользовательские данные отдельно от файлов пакета, поскольку обновление заменяет папку установленной версии. Служебный компонент распространяет файлы. Регистрация Windows-служб, запуск MSI и произвольные команды установки в этой реализации не предусмотрены.

## HTTP API

Клиент открывает системный браузер через `GET /api/auth/desktop?port=…&route=…&challenge=…`. Сервер сверяет `state`, обменивает код Alathea на токен с серверным секретом и читает профиль. После этого браузер передаёт одноразовый код на случайный локальный порт клиента. `POST /api/auth/exchange` принимает JSON с `code` и `verifier` и возвращает сеанс App Center. Сохранённый токен шифруется Windows DPAPI для текущего пользователя.

| Метод | Путь с Bearer-токеном |
| --- | --- |
| GET | `/api/me` |
| GET | `/api/catalog` |
| GET | `/api/apps/{id}/releases` |
| GET | `/api/apps/{id}/plan?release={releaseId}` |
| GET | `/api/releases/{releaseId}/download` |
| POST | `/api/auth/logout` |
